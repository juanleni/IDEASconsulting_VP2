2026-04-20
Modulo / area
Calidad / 8D / Paquete NotebookLM

Que se cambio
- Se agrego la tabla calidad_8d_acciones para soportar acciones separadas de D5 y D6.
- Se agrego CRUD en core_data.py para obtener, guardar y eliminar acciones 8D.
- Se conecto el modulo quality con las nuevas dependencias desde app.py.
- Se rediseño el editor 8D para trabajar con:
  - Reporte 8D
  - Ishikawa 6M
  - 5 Porques
  - Evidencia General
- D5 y D6 dejaron de ser solo texto y pasaron a funcionar como plan de accion con:
  - accion
  - responsable
  - fecha limite
  - progreso
  - evidencia
- Se mejoro Ishikawa para trabajar factores retenidos que luego se usan en 5 Porques.
- Se reorganizo el analisis de 5 Porques en paralelo:
  - ocurrencia
  - no deteccion
- Se convirtio D1 en equipo multifuncional:
  - nombre del participante
  - funcion / area
  - primer integrante marcado como lider
- Se genero paquete limpio para NotebookLM con resumen de estado y archivos clave.

Impacto funcional
- El modulo de calidad ya soporta una logica mucho mas cercana a un flujo automotriz / IATF real.
- El proyecto ahora tiene un paquete portable de contexto para NotebookLM.
- La estructura del editor de calidad es mas usable para consultoria y seguimiento.

Pendientes
- Permitir editar y eliminar acciones individuales D5/D6 desde la tabla.
- Mejorar aun mas la gestion de factores retenidos en Ishikawa.
- Permitir multiples arboles de 5 Porques por factor retenido.
- Llevar acciones D5/D6 al PDF ejecutivo.
